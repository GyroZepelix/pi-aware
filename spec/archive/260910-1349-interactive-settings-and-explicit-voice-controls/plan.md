# Plan: interactive settings and explicit voice controls

Work item: `260910-1349-interactive-settings-and-explicit-voice-controls`
Status: Planned
Created: 2026-09-10
Updated: 2026-09-10

## Goal

Replace bare `/pi-aware` toggling with a small in-Pi settings window for the complete persistent configuration, while retaining concise session voice controls through explicit command arguments.

## Context

- The parent work item is [`260904-2205-tmux-aware-tts-notifications`](../../active/260904-2205-tmux-aware-tts-notifications/plan.md). Current source at HEAD is authoritative over that older plan's completed implementation history.
- The current extension registers one `pi-aware` command whose argument-agnostic handler toggles session voice notifications. It reads strict global JSON during `session_start`, keeps normalized configuration in memory, and has deterministic injected adapters for filesystem reads, tmux, microphone detection, and speech.
- The session toggle behavior is documented by [`260907-1141-toggle-per-session-voice-notifications`](../../active/260907-1141-toggle-per-session-voice-notifications/plan.md). It starts enabled on every `session_start`, does not persist, and remains independent from speech and microphone failure warnings.
- Microphone suppression and the fifth config field were completed by [`260910-1045-suppress-tts-while-microphone-is-active`](../../archive/260910-1045-suppress-tts-while-microphone-is-active/outcome.md).
- The accepted persistent fields are `voice`, `rate`, `finishedPhrase`, `questionPhrase`, and `suppressWhileMicrophoneInUse`. Manual file edits currently require `/reload`.
- Pi 0.85.1 documentation supports command argument completion, blocking `ctx.ui.custom()` interfaces, centered overlays, remappable key handling, and `Input` components. `SettingsList` supports string choices but does not provide a complete mixed-field form, validation, or Save/Cancel/Reset actions.
- Pi documents `@earendil-works/pi-tui` as a bundled core package that extension packages import through a `"*"` peer dependency. The current checkout can resolve its installed `Input` implementation, but `package.json` does not yet declare that peer.
- Every blocking custom UI normally emits `ui_prompt_start`. The user confirmed that pi-aware must suppress the `question` announcement generated by opening its own settings window while preserving announcements for unrelated blocking UIs.
- Baseline `bun test` passes 19 tests with 125 expectations, and the working tree was clean before this planning item was created.

## Requirements

- R01: Keep one registered extension command named `pi-aware`, and change its description to advertise settings plus current-session voice controls.
- R02: Treat an empty or whitespace-only argument as a request to open a centered, blocking `pi-aware settings` overlay inside Pi TUI mode.
- R03: Expose all five accepted persistent fields in the settings overlay: optional voice, optional positive finite rate, required non-empty finished phrase, required non-empty question phrase, and boolean microphone suppression.
- R04: Initialize the settings draft from the normalized configuration currently active in the extension runtime. Represent omitted voice and rate as system-default values without inventing persisted values.
- R05: Provide keyboard-accessible Save, Cancel, and Reset actions. Reset changes only the staged draft to `DEFAULT_CONFIG`; it does not persist or apply until Save. Cancel, Escape from the top-level form, and closing without Save leave persistent and runtime configuration unchanged.
- R06: Validate the whole staged draft before Save using the same normalization rules as startup parsing. Trim strings, omit blank voice and rate, reject blank phrases, and reject rate text unless it converts to a positive finite number. Keep the overlay open and show a concise inline error when validation fails.
- R07: On valid Save, serialize one canonical flat JSON object with stable field order and a trailing newline, create the global extension config directory when needed, and atomically replace `<getAgentDir()>/extensions/pi-aware/config.json` through a same-directory temporary file and rename.
- R08: Apply a successfully persisted configuration immediately to subsequent announcements in the current runtime and show exactly one informational notification: `pi-aware: settings saved and applied.` Manual edits made outside the UI continue to require `/reload`.
- R09: If directory creation, temporary writing, or replacement fails, keep the prior target file when atomic replacement has not succeeded, keep the prior runtime configuration, clean up the temporary file best-effort, and issue one error notification that names the config path without exposing raw file contents.
- R10: Keep the persistent settings workflow independent from `voiceNotificationsEnabled`, `speechDisabled`, `speechWarningShown`, and `microphoneWarningShown`. Saving or resetting must not change the current session voice state or clear diagnostic latches.
- R11: Snapshot the complete normalized config when an announcement begins. An alert already awaiting tmux or microphone detection retains its starting phrase, voice, rate, and suppression setting; the newly saved config governs later alerts.
- R12: Suppress exactly the `ui_prompt_start` announcement caused by pi-aware opening its own settings overlay. Do not suppress unrelated blocking UI announcements, warnings, command feedback, or already-launched speech.
- R13: Parse one trimmed, case-insensitive command token. `/pi-aware t` and `/pi-aware toggle` invert the session voice state. `/pi-aware on` and `/pi-aware off` idempotently set it. Every state-changing command produces the existing exact enabled or disabled informational message.
- R14: `/pi-aware status` reports exactly one informational message in the form `pi-aware: voice notifications are enabled for this session.` or `pi-aware: voice notifications are disabled for this session.` and changes no state.
- R15: Any non-empty argument other than `t`, `toggle`, `on`, `off`, or `status`, including additional tokens, must change no state and show exactly one warning: `pi-aware: usage: /pi-aware [t|toggle|on|off|status]`.
- R16: Add argument completion entries for `t`, `toggle`, `on`, `off`, and `status`, with concise labels or descriptions. Completion must not suggest the empty settings action.
- R17: Bare `/pi-aware` outside TUI mode must not call `ctx.ui.custom`, write configuration, or mutate session voice state; it must report that settings require TUI mode through the available UI notification channel.
- R18: Preserve session-start reset to voice enabled, config all-or-default startup validation, macOS and mode gates, lifecycle generation guards, microphone fail-open behavior, tmux lookup, speech failure handling, overlap, native helper behavior, package platform constraints, and one runtime extension source file.
- R19: Add `@earendil-works/pi-tui: "*"` to `peerDependencies` before introducing its runtime UI imports, and add `@earendil-works/pi-tui: "0.85.1"` as the sole development dependency so the checkout's Bun tests can resolve the peer. Do not add runtime `dependencies`, another UI library, or another extension entry point.
- R20: Extend deterministic Bun coverage for command grammar, completion, form staging and validation, self-prompt suppression, atomic-write adapter outcomes, immediate application, config snapshots, lifecycle safety, and all existing regressions without touching the real agent directory or producing speech.
- R21: Update README behavior, command usage, configuration, reload semantics, settings controls, validation, immediate application, and no-provider smoke guidance.

## Assumptions

- "Small window" means Pi's centered `ctx.ui.custom()` overlay rather than a sequence of built-in prompts or a full-screen editor. Revisit if overlay rendering proves unusable in supported terminal sizes.
- Reset restores the staged defaults and still requires Save, as disclosed in the confirmed understanding. Revisit if one-step destructive reset is explicitly requested.
- Command matching trims surrounding whitespace and lowercases one token. Multiple tokens are invalid rather than partially accepted.
- `on` and `off` always issue the exact state message, even when the requested state is already current, so every state command has observable feedback.
- Blank voice and rate mean macOS system defaults. Blank phrases remain invalid because silent or whitespace-only event phrases violate the existing config contract.
- A successfully saved canonical file may include default-valued phrase and suppression fields while omitting voice and rate. No preservation of comments, whitespace, key ordering, or unknown fields from a manually edited file is required because JSON comments and unknown keys are already invalid.
- Concurrent saves from different Pi processes use atomic replacement but remain last-writer-wins. Cross-process locking and merge conflict UI are excluded.
- Pi 0.84.4 remains the documented minimum because custom UI and overlays predate it; current installed Pi 0.85.1 is the planning and smoke-test reference.
- Minor defaults exclude unrelated cleanup, dependencies beyond the required bundled-core peer plus its approved Pi TUI `0.85.1` development install, migrations, commits, pushes, publication, provider calls, and wiki changes during planning.

## Design

### Command grammar and session state

Keep command registration at extension factory time. Add a small parser that trims the complete `args` string and accepts only these normalized forms:

| Invocation | Result |
| --- | --- |
| `/pi-aware` | Open settings overlay in TUI mode |
| `/pi-aware t` | Invert session voice state |
| `/pi-aware toggle` | Invert session voice state |
| `/pi-aware on` | Set session voice state to enabled |
| `/pi-aware off` | Set session voice state to disabled |
| `/pi-aware status` | Report current session voice state without mutation |
| Any other non-empty argument | Show usage warning without mutation |

Centralize enabled and disabled state notification construction so toggle, on, and off retain the current exact messages. Add `getArgumentCompletions` with the five accepted tokens and descriptions. Keep the preference boolean separate from runtime eligibility and failure state.

### Settings overlay

Use `ctx.ui.custom()` with `{ overlay: true }` and centered bounded dimensions appropriate for five fields, actions, inline validation, and help text. Keep rendering within the supplied width and request a render after state changes.

Build one staged form component in `extensions/pi-aware.ts` from Pi's theme and injected keybindings plus `Input` from `@earendil-works/pi-tui`. The form must:

1. Render a title and rows for Voice, Rate, Finished phrase, Question phrase, and Suppress while microphone is active.
2. Show `system default` for omitted voice and rate without persisting that label.
3. Navigate rows and actions with remappable select keys and Tab/Shift-Tab where practical.
4. Route text editing through `Input`, propagate focus for cursor and IME behavior, and distinguish edit-mode Escape from top-level Cancel.
5. Toggle microphone suppression as an on/off value.
6. Render Save, Cancel, and Reset as reachable actions and show concise footer key hints.
7. Keep all edits local until Save returns a validated normalized config.
8. Keep validation errors in the form until the user corrects a field, resets, or cancels.

`SettingsList` may be used for bounded choice rows, but it must not force immediate persistence or replace the staged multi-field form contract. Prefer the simplest composition that preserves testable navigation and field editing.

### Self-prompt suppression

Before calling `ctx.ui.custom`, arm a one-shot flag for pi-aware's own next `ui_prompt_start`. The event handler consumes that flag and returns without calling `announce`. Clear the flag in a `finally` path if the custom UI fails or does not emit the expected prompt event. Do not use a broad `settingsOpen` speech gate that could suppress unrelated prompts for the entire time the window remains open.

### Validation and serialization

Keep one normalization path for startup JSON and staged form values so field rules cannot drift. Convert the rate input only at form validation time. Represent a normalized config as a fresh object and never mutate the active config in place.

Serialize valid settings with two-space indentation, fixed schema order, omitted optional voice/rate when blank, and a final newline. The serialized document must round-trip through the startup parser to the same normalized config before persistence begins.

### Atomic persistence and immediate application

Extend the injected dependency seam with a narrowly scoped config writer. Its production implementation will:

1. Create the config directory recursively.
2. Create a uniquely named temporary file in that directory.
3. Write the complete canonical JSON.
4. Rename the temporary file over `config.json` on the same filesystem.
5. Remove the temporary file best-effort on failure.

Tests inject the writer and never touch the real filesystem. The command handler applies `config = savedConfig` only after the writer resolves successfully and the initiating lifecycle is still current. On failure it retains the prior object and reports the bounded path-specific error. If a lifecycle replacement makes the command result stale, do not apply configuration or notify through the old context.

### Announcement snapshots

Change announcement entrypoints to select the phrase from a single copied config snapshot at invocation time rather than passing a phrase while reading other config fields later. Use that snapshot for microphone suppression, phrase, voice, and rate throughout the asynchronous flow. Existing manual-toggle checks continue to use final session state at each gate, matching the established off-then-on behavior.

### Package and documentation

Add `@earendil-works/pi-tui: "*"` beside the coding-agent peer because official package guidance requires bundled core imports to be peer-declared. Also add Pi TUI `0.85.1` as the sole development dependency and retain the generated Bun lockfile so direct imports resolve in the checkout's tests. The runtime package remains a peer, not a production dependency. The user explicitly approved this narrow package metadata and installation correction after the initial Bun run disproved the peer-only local-resolution assumption.

Update README to make bare settings and argument controls discoverable. State that in-Pi Save applies immediately, manual JSON edits still require `/reload`, Reset is staged until Save, session voice state is independent, and the settings window does not speak its own question alert.

## Risks and blockers

- Opening a custom settings UI emits the same `ui_prompt_start` event used for attention speech. A broad guard could hide unrelated prompts, so use and test a one-shot self-prompt suppression flag.
- Overlay mode is documented as experimental. Keep the component width-bounded, avoid advanced overlay focus behavior, and retain a focused no-provider smoke at the installed Pi version.
- `SettingsList` cannot directly model validated text and numeric fields with staged Save. A custom form adds keyboard and focus complexity; mitigate with Pi's `Input`, injected keybindings, small state transitions, and component-level tests.
- A static `@earendil-works/pi-tui` import changes package metadata and needs local test resolution. Official guidance supports the runtime peer; the user explicitly approved exact Pi TUI `0.85.1` as the sole development dependency after the peer-only Bun import failed.
- Atomic rename prevents partial JSON but does not merge concurrent edits. Document last-writer-wins behavior and avoid cross-process locks in this scope.
- A save can race lifecycle replacement. Capture the lifecycle generation, avoid applying or notifying through stale state, and test a deferred writer.
- Applying config immediately can otherwise mix old phrase and new voice/rate inside one pending alert. Snapshot the full config at announcement start and test both old pending and new subsequent behavior.
- Canonical UI Save replaces formatting and any invalid manual content. This is accepted because the existing schema rejects unknown fields and JSON has no comment contract; document that Save writes normalized JSON.
- Real Save changes a file outside the repository, and audible tests produce host side effects. Keep injected tests primary and preserve explicit approval gates for manual verification.
