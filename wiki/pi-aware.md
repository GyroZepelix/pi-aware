# pi-aware extension

Load this page when changing the extension's alerts, tmux lookup, configuration, packaging, or tests.

## Runtime contract

- **Attention events are lifecycle-driven** - Announce `question` for every `ui_prompt_start` and `finished` for every `agent_settled`; do not infer questions from assistant prose. `finished` means automatic work stopped, including aborts and unrecoverable failures. ([source](../extensions/pi-aware.ts))
- **Voice alerts have a session-local toggle** - `/pi-aware` toggles both question and finished speech, reports the state in the UI, and starts enabled on every `session_start`, including reload and session replacement. The in-memory preference does not suppress warnings, cancel speech already playing, or clear the independent speech-failure latch. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Announcements run only in supported macOS TUI sessions** - The package supports macOS 26.0 or newer on Apple Silicon (`arm64`). Other pi modes stay silent; interactive non-macOS sessions warn once and remain disabled. Package metadata rejects unsupported operating systems and CPUs. ([source](../extensions/pi-aware.ts), [manifest](../package.json), [documentation](../README.md))
- **Speak the current tmux window index** - Target the exact process pane through `TMUX_PANE`, query `#{window_index}` before every alert, and append only valid non-negative integer output. Missing tmux state, lookup failure, or invalid output silently falls back to the phrase without a number. ([source](../extensions/pi-aware.ts))
- **Microphone use suppresses new speech by default** - After tmux lookup and immediately before speech, run the bundled CoreAudio helper for a point-in-time check. If any process has active audio input, silently skip the alert. The manual `/pi-aware` state and microphone result are independent gates: speech requires manual enable plus inactive input, and an in-flight alert uses the final manual state. ([source](../extensions/pi-aware.ts), [helper](../native/pi-aware-mic-status.c), [tests](../tests/pi-aware.test.ts))
- **Detection fails open and remains diagnostic** - A helper error, timeout, nonzero exit, or invalid token warns once per runtime and allows speech, while later alerts retry. Detection warnings remain visible even if manual speech is off or the speech-failure latch is set; lifecycle-stale failures do not warn through a newer context. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Speech is asynchronous and may overlap** - Launch `/usr/bin/say` without a shell or playback wait. A spawn error or unsuccessful exit warns once and disables later speech until reload or session replacement. ([source](../extensions/pi-aware.ts))

## Configuration

- **Configuration is global and reload-based** - Read `<getAgentDir()>/extensions/pi-aware/config.json` at `session_start`; do not add project config or file watching without a new decision. ([source](../extensions/pi-aware.ts))
- **Validation is strict and all-or-default** - The optional keys are `voice`, `rate`, `finishedPhrase`, `questionPhrase`, and boolean `suppressWhileMicrophoneInUse`, which defaults to `true`. Unknown or invalid fields reject the entire file, warn once, and use all defaults; a missing file silently uses defaults. Setting suppression to `false` skips helper invocation. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))

## Package and testing

- **Keep one TypeScript extension plus one first-party native adapter** - The package exposes only `extensions/pi-aware.ts` to pi and adds no runtime or development dependencies. Normal pi installation uses the packaged `arm64`, macOS-26-targeted `bin/pi-aware-mic-status` executable and does not rebuild it; C source and `npm run build:mic-helper` exist for contributors only. Users do not install CoreAudio or compiler tools. ([manifest](../package.json), [source](../native/pi-aware-mic-status.c), [build](../scripts/build-mic-status.sh))
- **Preserve a deterministic, runnable Mach-O identity** - Do not remove `LC_UUID`: macOS 26 dyld aborts a helper without it. The build disables linker ad-hoc signing, replaces the random UUID with a content-derived UUID, then signs with stable identifier `com.gyrozepelix.pi-aware.mic-status`; repeated same-environment builds must have matching hashes. ([build](../scripts/build-mic-status.sh), [verification](../spec/archive/260910-1045-suppress-tts-while-microphone-is-active/verification.md))
- **Keep the pi value import lazy** - The default extension dynamically imports `getAgentDir` so dependency-free Bun tests can import the runtime without resolving the undeployed peer package. Type-only pi imports remain static. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Verify TypeScript and native seams** - Run `bun test`, rebuild the helper twice and compare hashes, inspect architecture, deployment target, UUID, signing, linkage, executable mode, package contents, and helper token output, then use `pi -e .` for no-provider loading. Real microphone-active, audio, persistent-config, or provider-backed lifecycle checks require explicit approval because they produce host side effects or provider cost. ([README](../README.md), [plan](../spec/archive/260910-1045-suppress-tts-while-microphone-is-active/plan.md), [verification](../spec/archive/260910-1045-suppress-tts-while-microphone-is-active/verification.md))
