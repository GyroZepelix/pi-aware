# pi-aware extension

Load this page when changing the extension's alerts, tmux lookup, settings, configuration, packaging, or tests.

## Runtime contract

- **Attention events are lifecycle-driven** - Announce `question` for every unrelated `ui_prompt_start` and `finished` for every `agent_settled`; do not infer questions from assistant prose. `finished` means automatic work stopped, including aborts and unrecoverable failures. The settings overlay consumes its own one-shot prompt event so opening `/pi-aware` does not announce itself. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Voice controls are session-local and explicit** - Bare `/pi-aware` opens settings. `/pi-aware t` and `/pi-aware toggle` invert both question and finished speech; `on` and `off` set the state idempotently; `status` reports it without mutation. State starts enabled on every `session_start`, including reload and session replacement. It does not suppress warnings, alter persistent settings, cancel speech already playing, or clear diagnostic latches. Unknown or multi-token arguments show usage. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Announcements run only in supported macOS TUI sessions** - The package supports macOS 26.0 or newer on Apple Silicon (`arm64`). Other pi modes stay silent; interactive non-macOS sessions warn once and remain disabled. Package metadata rejects unsupported operating systems and CPUs. ([source](../extensions/pi-aware.ts), [manifest](../package.json), [documentation](../README.md))
- **Speak the current tmux window index** - Target the exact process pane through `TMUX_PANE`, query `#{window_index}` before every alert, and append only valid non-negative integer output. Missing tmux state, lookup failure, or invalid output silently falls back to the phrase without a number. ([source](../extensions/pi-aware.ts))
- **Microphone use suppresses new speech by default** - After tmux lookup and immediately before speech, run the bundled CoreAudio helper for a point-in-time check. If any process has active audio input, silently skip the alert. The manual session state and microphone result are independent gates: speech requires manual enable plus inactive input, and an in-flight alert uses the final manual state. ([source](../extensions/pi-aware.ts), [helper](../native/pi-aware-mic-status.c), [tests](../tests/pi-aware.test.ts))
- **Detection fails open and remains diagnostic** - A helper error, timeout, nonzero exit, or invalid token warns once per runtime and allows speech, while later alerts retry. Detection warnings remain visible even if manual speech is off or the speech-failure latch is set; lifecycle-stale failures do not warn through a newer context. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Each announcement snapshots persistent configuration** - Copy phrase, voice, rate, and microphone-suppression settings when the alert begins. A Save while tmux or microphone work is pending governs later alerts and cannot mix new values into the in-flight alert. Manual voice state remains a final gate rather than part of this snapshot. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Speech is asynchronous and may overlap** - Launch `/usr/bin/say` without a shell or playback wait. A spawn error or unsuccessful exit warns once and disables later speech until reload or session replacement. ([source](../extensions/pi-aware.ts))

## Settings and configuration

- **Configuration is global with two application paths** - Read `<getAgentDir()>/extensions/pi-aware/config.json` at `session_start`. Manual file edits require `/reload`; a successful in-Pi Save applies immediately to later alerts. Do not add project config, file watching, or session-toggle persistence without a new decision. ([source](../extensions/pi-aware.ts), [documentation](../README.md))
- **The settings overlay stages the complete schema** - Bare `/pi-aware` in TUI presents optional voice and rate, required finished and question phrases, and boolean microphone suppression. Save validates the complete draft, Cancel or top-level Escape changes nothing, and Reset stages defaults but still requires Save. Validation errors stay visible until the complete draft is corrected, reset, or canceled. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Save is atomic before runtime replacement** - Serialize normalized JSON with stable field order and a trailing newline, write a unique temporary file in the target directory, then rename it over `config.json`. On failure, clean the temporary path best-effort and retain the previous runtime config. Apply only after persistence succeeds and the lifecycle is still current. Concurrent Pi processes remain last-writer-wins. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))
- **Validation is strict and all-or-default** - Accepted keys are `voice`, `rate`, `finishedPhrase`, `questionPhrase`, and boolean `suppressWhileMicrophoneInUse`, which defaults to `true`. Unknown or invalid startup fields reject the entire file, warn once, and use all defaults; a missing file silently uses defaults. Blank voice and rate in the UI mean system defaults. Setting suppression to `false` skips helper invocation. ([source](../extensions/pi-aware.ts), [tests](../tests/pi-aware.test.ts))

## Package and testing

- **Keep one TypeScript extension plus one first-party native adapter** - The package exposes only `extensions/pi-aware.ts` to pi and has no runtime dependencies. Normal installation uses the packaged `arm64`, macOS-26-targeted `bin/pi-aware-mic-status` executable and does not rebuild it; C source and `npm run build:mic-helper` exist for contributors only. Users do not install CoreAudio or compiler tools. ([manifest](../package.json), [source](../native/pi-aware-mic-status.c), [build](../scripts/build-mic-status.sh))
- **Declare and resolve Pi TUI through separate contracts** - Keep `@earendil-works/pi-tui` as a runtime peer at `"*"`, pin 0.85.1 as the sole development dependency, and retain `bun.lock`. A peer declaration alone did not let Bun resolve the static `Input` import in this checkout; run `bun install --frozen-lockfile` before tests. ([manifest](../package.json), [lockfile](../bun.lock), [verification](../spec/archive/260910-1349-interactive-settings-and-explicit-voice-controls/verification.md))
- **Preserve a deterministic, runnable Mach-O identity** - Do not remove `LC_UUID`: macOS 26 dyld aborts a helper without it. The build disables linker ad-hoc signing, replaces the random UUID with a content-derived UUID, then signs with stable identifier `com.gyrozepelix.pi-aware.mic-status`; repeated same-environment builds must have matching hashes. ([build](../scripts/build-mic-status.sh), [verification](../spec/archive/260910-1045-suppress-tts-while-microphone-is-active/verification.md))
- **Isolate no-provider TUI smoke sessions** - Do not use plain `pi -e .` when the verification claim requires a fresh no-provider session; it can restore active work and interpret scripted commands as provider steering. Use `pi --no-session --offline --approve --no-extensions -e extensions/pi-aware.ts --no-skills --no-prompt-templates --no-context-files`, disable voice before opening settings, and Cancel without Save. ([verification](../spec/archive/260910-1349-interactive-settings-and-explicit-voice-controls/verification.md), [documentation](../README.md))
- **Verify deterministic and host-side seams separately** - Run `bun test`, frozen installation, direct Pi TUI import, package metadata checks, `npm pack --dry-run`, repository checks, and the isolated no-provider smoke. Rebuild and inspect the native helper when its source or build changes. Real global config writes, microphone-active behavior, audio, persistent restoration, provider-backed lifecycle, publication, and remote installation require explicit approval and must remain reported as unverified when skipped. ([documentation](../README.md), [verification](../spec/archive/260910-1349-interactive-settings-and-explicit-voice-controls/verification.md))
